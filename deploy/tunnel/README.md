# Lane A demo deployment

For the demo, start with the [demo tunnel runbook](../../docs/DEMO-TUNNEL.md): it compares this two-hostname setup with a consent-only one and holds the phone checklist.

Use the `izwi-demo` named tunnel for the isolated build. The team account owner adds `studio.<team-zone>` and `consent.<team-zone>` within an existing Cloudflare zone. Use a restricted self-hosted Cloudflare Access application on the whole Studio hostname. Configure its audience in the ingress rule so the connector verifies Access before forwarding. Keep the Studio app sign-in enabled inside Access. [Cloudflare origin parameters](https://developers.cloudflare.com/tunnel/reference/origin-parameters/)

1. Use dedicated storage, SQLite, application secrets and team-only demo accounts. Bind the app origin to loopback at port 3187. Start the worker with the same storage, database and environment. Apply migrations to a backup copy before deploying with data.
2. Apply the environment template and the tunnel config. Keep real credentials in the account owner's secret store or ignored environment file. Validate the final ingress with `cloudflared tunnel ingress validate`. Use the named tunnel only after establishing the Access policy.
3. From a clean unauthenticated browser confirm Studio displays Access, the consent host serves only consent pages and scoped media, and the consent host denies Studio, sign-in, API and listing routes outside the allowlist. Then verify authorised Studio sign-in, consent submission, token expiry, scoped media and rights-gated export.
4. Keep the trial policy empty until allowed models, provider privacy settings and real upstream pricing are verified for this account. Enter provider keys in Studio → Run on. Reserve worst-case cost per request, use a dedicated upstream project with provider-side limits where offered, and hold total reservations at or below USD 1 for Meta and USD 0.50 for AI/ML API. Set zero paid allowance for Groq, Gemini and OpenRouter and confirm the exact free routes. Test all five first with non-sensitive text. A model that passes its connection test still needs a successful product run.
5. Roll back by stopping the dedicated tunnel and app and restoring the isolated pre-migration database and storage together if needed. Capture the build identifier, dated observations and redacted outputs in the Lane A build log.

Run Ollama acceptance on the laptop-local app with hosted mode and hosted trial mode disabled. The public hosted process denies private provider endpoints. Keep public consent fixtures and model QA fixtures separate.
